# 06 · 工具与工作流分册

> **与主结论的关系**：工具带来的效率优势不会自动平均分配。**能接上足够强智能的人，会先拿到优势，再用优势换更多资源**（公理五·智能入口定理）。
> 所以这一册不回答"哪个工具好"，回答的是"**谁在用、谁没用上、差距怎么长出来的**"。

---

## 一、判断一个工具值不值得用（六问）

| # | 问题 | 不合格的信号 |
|---|---|---|
| 1 | 它替换掉的是**哪一步**？ | 说不出具体某一步 = 玩具 |
| 2 | 第一次能把活干完要多久？ | 超过半天没跑通第一轮 = 接入成本过高 |
| 3 | 每周维护要花多少时间？ | 需要持续调提示词 / 喂数据 = 隐性成本 |
| 4 | 输出要人复核多少？ | 复核时间 ≥ 手工做的时间 = 白干 |
| 5 | 明天涨价 / 关停 / 降智，换掉的代价？ | 数据导不出、流程绑死 = 高风险 |
| 6 | 不用它现在怎么做？差多少？ | 差距不明显 = 不需要 |

## 二、完整成本（六项，后四项最容易被忽略）

订阅费 ＋ 学习时间 ＋ 维护时间 ＋ 复核时间 ＋ 出错返工 ＋ **退出成本**

> 大多数"省时工具"的真实成本，藏在后四项里。**退出成本最贵，也最没人算。**

## 三、流程拆解：每一步看三个属性

| 属性 | 判断 | 含义 |
|---|---|---|
| 可完整写下来吗 | 能被文字化、步骤固定 | 是 → 优先交给 AI |
| 出错谁承担 | 需要人签字、可追责 | 是 → 人必须在环中（对应公理三） |
| 必须到现场吗 | 需要身体到场、非标环境 | 是 → AI 只能做准备（对应公理四） |

**排序原则**：先自动化「高频 + 低风险 + 可验证」的那一步。第一步失败了，后面全部推不动。

## 四、把 Agent 骨架立起来（当你要长期用同一个流程）

1. **先写验收标准**，再写提示词。说不清"怎样算做完"，提示词写不长。
2. **约束写进系统提示，不靠临时叮嘱**。临时的规矩会随对话流失。
3. **记忆分层**：会话内上下文 / 长期偏好 / 项目事实，三层分开存，不要混在一起喂。
4. **一次跑通 ≠ 次次跑通**。跑通后立刻补：边界条件、失败样例、重试规则。
5. **留退出路径**：提示词与数据能带走，流程不绑死在单一工具上。

## 五、三档结论规则

| 结论 | 触发条件 |
|---|---|
| **现在接** | 能明确替换掉一个高频步骤；第一轮一小时内跑通；退出方案清晰 |
| **观察 3 个月** | 方向对但工具还新；需要持续喂数据才见效；退出方案不明确 |
| **不接** | 说不出替换哪一步；复核时间 ≥ 手工时间；无退出方案 |

## 六、常见的三种误判

| 误判 | 表现 | 修正 |
|---|---|---|
| 工具先行 | 先看有什么工具，再想能干嘛 | 先拆流程，再找工具 |
| 一步到位 | 想一次改完整个流程 | 一次只改一步，跑一周再动下一步 |
| 忽略复核 | 默认 AI 输出可以直接用 | 复核时间必须计入成本 |

## 七、挂回主线的一句话

**工具不是把人的差距抹平，是把差距的兑现速度变快。** 判断一个工具值不值得用，最终要问的是：它让**谁**先跑起来了，而**谁**还在观望。
